AI on the Terminal

Hand an AI agent a real folder, watch it work, and keep an undo button. Works with any agent.

Any agent, Mac or Windows ~40 minutes hands-on

A written lesson

There is no video for this one. Every step is on this page, in order. Keep it open next to your terminal and work down it. Prices and free plans were checked against each company's own pages on 3 October 2026; they change often, so the date matters.

Quick Start

Five moves. The detailed guide below walks through each one.

In Level 1 the AI lived in a browser tab. You copied its answers out and pasted them into files yourself. A terminal agent skips that step: it opens your files, edits them and runs commands on your computer. It has hands. This lesson teaches one safe way to work with those hands, and the same method works whichever agent you choose.

The one habit to take away

Save a restore point before the agent touches anything. Read every request it makes before you say yes. If it goes wrong anyway, one command puts everything back.

What happened to "completely free"?

A year ago you could install OpenCode and code all day on a free model. That era ended in stages. In February 2026 OpenCode's release notes started mentioning a "free usage limit" (it does not publish the number), and it now sells a paid plan, OpenCode Go. Its free models also rotate: OpenCode's public model list (models.dev) shows 36 free models since August 2025, and 26 of them have already been retired. Google and Alibaba closed their free terminal tiers outright in 2026. Free still exists, but it moves. If a free model vanishes from your list, pick another one; that is normal, not a fault on your side.

Three rules for free routes

Practice files only

Most free plans can use what you type to train or improve their models. Never give a free agent customer data, passwords or anything private. The café folder in this lesson is made up for exactly that reason.

Expect a wall

Every free route has a limit, and most do not publish the number. When you hit it, wait, switch model, or switch agent. Your folder and restore points stay put.

Check the date

Detailed Step-by-Step Guide

Seven steps, from no agent to a finished session report.

1 Choose your agent

Pick the first line that is true for you:

  • You pay for ChatGPT (Plus or above): use Codex CLI.
  • You pay for Claude (Pro or above): use Claude Code.
  • You pay for nothing and want the simplest free start: use OpenCode. If you did the Install OpenCode lesson, it is already on your computer.
  • You pay for nothing and OpenCode's free models are busy: try Copilot CLI or Antigravity CLI.

The agents differ in price, models and polish. The way you work with them is the same, and that is what the rest of this lesson teaches.

2 Install it and sign in

Open your terminal. On a Mac, press Cmd + Space, type Terminal, press Enter. On Windows, press the Windows key, type PowerShell, press Enter. Then open the block for your agent.

OpenCodeFree models

Follow the Install OpenCode lesson in this level (about 8 minutes), then come back here. It covers the install for Mac and Windows, signing in with /connect, and choosing a free model with /models.

GitHub Copilot CLIFree plan

Mac:

curl -fsSL https://gh.io/copilot-install | bash

Windows: Copilot CLI needs PowerShell 7. Windows ships with an older version, so install the new one first, close the window, then open PowerShell 7 from the Start menu:

winget install Microsoft.PowerShell

Then, in PowerShell 7:

winget install GitHub.Copilot

Start and sign in: type copilot and press Enter. If it says you are not signed in, type /login and follow the browser steps. If GitHub says you have no Copilot plan, open github.com/features/copilot/plans, choose Free, then try again.

Antigravity CLI (Google)$0 plan

Mac:

curl -fsSL https://antigravity.google/cli/install.sh | bash

Windows (PowerShell):

irm https://antigravity.google/cli/install.ps1 | iex

Start: type agy and press Enter. The first launch walks you through a short setup, including whether to trust the folder you are in. Follow its prompts to sign in.

Codex CLI (OpenAI)ChatGPT Plus and up

Mac:

curl -fsSL https://chatgpt.com/codex/install.sh | sh

Windows (PowerShell):

powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"

Start and sign in: type codex and press Enter, then choose Sign in with ChatGPT and finish in the browser.

Claude Code (Anthropic)Claude Pro and up

Mac:

curl -fsSL https://claude.ai/install.sh | bash

Windows (PowerShell):

irm https://claude.ai/install.ps1 | iex

Start and sign in: type claude and press Enter, then follow the browser prompts to log in with your Claude account.

"command not found" after installing?

Close the terminal window completely, open a new one, and try again. A new window picks up newly installed programs. If the installer printed a line telling you to add something to your PATH, copy that line, run it, and open a new window. Those two moves fix most install problems on Mac and Windows.

Once the agent starts, quit it for now (type /exit, or press Ctrl + C twice). You will start it again inside the practice folder.

3 Get the practice folder and open a terminal in it

driftwood-cafe.zip
Nine messy files from a made-up café in Westport. Notes, two menus that disagree, reviews, a draft email and a small website.

Unzip it somewhere easy to find, such as your Desktop: double-click it on a Mac, or right-click and choose Extract All on Windows. You should now have a folder called driftwood-cafe with the nine files inside.

An agent works on the folder your terminal is "in", so the next job is to put the terminal inside driftwood-cafe:

  • Mac: in Terminal, type cd followed by a space. Drag the driftwood-cafe folder from Finder into the Terminal window (this types its location for you), then press Enter.
  • Windows 11: open the driftwood-cafe folder in File Explorer, right-click an empty space inside it, and choose Open in Terminal.
  • Windows 10: open the folder in File Explorer, click the address bar, type powershell, press Enter.
  • Copilot on Windows: if copilot is not recognised in that window, open PowerShell 7 from the Start menu instead, type cd and a space, drag the folder into the window, and press Enter.

Check you are in the right place. Type this and press Enter:

ls

You should see the café's files listed, including menu.csv and index.html. ls means "list what is here" and works on Mac and in PowerShell. If you see other files, you are in the wrong folder: repeat the step above.

4 Save a restore point with git

Git is a tool that takes snapshots of a folder. Developers use it to track changes; you will use it as an undo button for everything the agent does. Check whether you have it:

git --version
  • A version number like git version 2.4x: you have it, skip ahead.
  • Mac, a pop-up offering to install "command line developer tools": click Install, wait for it to finish, then run git --version again.
  • Windows, "not recognized": run winget install --id Git.Git -e, close the terminal, open a new one in the folder again (step 3), and check once more.

The first time you use git, tell it your name and email. These label your snapshots and stay on your computer. Run both lines, with your own details inside the quotes:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Now take the first snapshot. Run these three lines, one at a time:

git init
git add -A
git commit -m "Before the agent"

The last line should report something like 9 files changed. That snapshot is your restore point. On Windows, git may also print warnings about "LF" and "CRLF" or a hint about branch names; they are harmless.

5 Start the agent and learn to read its requests

From inside driftwood-cafe, start your agent: opencode, copilot, agy, codex or claude. If it asks whether you trust this folder, say yes: it is the practice folder.

Before an agent edits a file or runs a command, most agents stop and ask you. A request usually looks like this:

Agent wants to run: mkdir menus && mv menu.csv "copy of menu.csv" menus/ Allow? [y] yes [a] always [n] no, tell it what to do instead

An illustration. The exact wording and keys differ between agents.

Read the command. Ask yourself: is it only touching files in this folder, and is it what I asked for? If yes, allow it. If you are unsure, say no and ask the agent to explain in plain English. Two warnings:

  • OpenCode does not ask by default. It lets the agent edit files and run commands straight away. That is fine in the practice folder, because your restore point covers it.
  • Never start an agent with a flag containing yolo, dangerously or bypass on your real files. Those switch the questions off entirely.

6 Run the four missions

Paste each prompt into the agent, one at a time. Wait for each to finish before the next.

Mission 1 · Look

Agents can read everything in a folder. Start with a request that changes nothing.

Read every file in this folder. Do not change anything yet. Tell me in five bullet points what this business is and what needs doing. Then list anything you found that should not be lying around in plain text.

Notice: did it find the Wi-Fi password in Untitled 3.txt? An agent sees every file you point it at. That is why real passwords and private data never go into a folder you share with an agent, and why the free routes above get practice files only.

Mission 2 · Organise

Knowledge work, not code. This is where most people realise these agents are not just for programmers.

Organise this folder for the café owner. Sort the files into a few sensible subfolders. The two menu files disagree: merge them into one menu.csv, use the newest prices from the notes, and list every conflict you resolved. Read the reviews and tell me if there is a pattern. Rewrite the email to Seamus so it is firm but polite, as a new file; do not send anything. Finally, write INDEX.md explaining where everything now lives. Show me your plan before you start.

Notice: the agent should show its plan and may ask you a question first. The two menus disagree on the flat white price and the notes do not settle it, so a careful agent asks instead of guessing. Answer it (any price is fine), then type Go ahead. It will ask before moving files unless you use OpenCode. When it finishes, open the folder in Finder or File Explorer and look at what changed; it may also have renamed files.

Mission 3 · Fix

Now a small code change. The website shows the old opening hours.

The opening hours on index.html are out of date. Use the owner's notes to update them. Change nothing else on the page, then tell me exactly which lines you changed.

Notice: open index.html in your browser to check the hours. Then save this good state as a second snapshot. Exit the agent (or open a second terminal window in the same folder) and run:

git add -A
git commit -m "Organised and fixed hours"
Mission 4 · Break it, then undo it

You will only trust the undo button once you have pressed it. Start the agent again if you exited, and ask it to do something destructive on purpose:

This is a test of my undo button. Delete every .txt file in this folder and its subfolders.

Approve it. Then exit the agent (or switch to your second terminal window) and look at the damage:

git status

Git lists every deleted file. Now bring them all back:

git restore --staged --worktree .

Notice: run git status again. It should say nothing to commit, working tree clean, and the files are back in the folder. In plain English the command says: put every file in this folder (the full stop) back the way the last snapshot had it. It works however the agent deleted them. It only restores files that were in your last snapshot, which is why you snapshot before each mission.

7 Have the agent write your session report

Start the agent again and paste this:

Write SESSION-REPORT.md in this folder. Include: which agent and model you are; a short summary of each of the four missions we did; every file you created, moved or changed; the output of running git log --oneline; and one thing from this session that a careful person should double-check. Keep it under one page.

Read the report. Correct anything that is wrong (you can ask the agent to fix it). Then take a final snapshot:

git add -A
git commit -m "Session report"

What you can now do

You picked an agent, gave it a folder, watched it read, organise and fix real files, approved or refused its requests, and undid its work with one command. Every later Level 2 lesson builds on this: same folder habit, same restore points, whichever agent you use.

Submit Your Work

One public link to your SESSION-REPORT.md.

Share your SESSION-REPORT.md as a public link. The quickest way: open gist.github.com (you are already signed in to GitHub from Level 1), name the file SESSION-REPORT.md, paste the report in, and click Create public gist. A Google Doc or Notion page set to "anyone with the link" also works.

Your report must show the git log --oneline output with at least two snapshots ("Before the agent" and "Organised and fixed hours"). That is the proof you used restore points.

Troubleshooting

The problems learners hit most, and the fix for each.

Your agent can help

Once an agent is running, it is the best troubleshooter you have. Paste the error and ask "what does this mean and what should I do?". Before that, paste it into ChatGPT, Claude or Gemini in the browser.

"command not found" or "is not recognized"

Close the terminal completely and open a new one. If it still fails, run the install line again and read its last few lines for an error.

Windows: "running scripts is disabled on this system"

Run this once, then try the install again: Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

git: "Please tell me who you are"

You skipped the two git config lines in step 4. Run them, then repeat the commit.

git: "not a git repository"

Your terminal is not inside driftwood-cafe. Go back to step 3, open the terminal in the folder, and check with ls.

OpenCode: "OpenCode 1.18.0 or newer is required to use the free tier"

Your OpenCode is older than its free models now accept. Run opencode upgrade, then start it again.

The agent says you hit a limit, or the model is unavailable

That is the free-route wall. Wait and try later, choose another free model (in OpenCode, type /models), or switch to another agent from the table. Your folder and snapshots do not care which agent you use.

The agent changed something you did not want

Exit the agent and run git restore --staged --worktree . to return to your last snapshot. If it created new files you do not want, delete them in Finder or File Explorer; git restore only brings back files from the snapshot.

The agent asks to sign in again and again

Finish the sign-in in the browser tab it opens, all the way to the "you can close this page" message. If your browser blocks pop-ups, copy the link the agent prints into the browser yourself.
