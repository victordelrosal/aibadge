1. What runs now, and how to stop it

A launchd job, com.fiveinnolabs.aibadge-autorun, runs certs-system/scripts/grading/autorun.mjs at 08:30, 13:30 and 17:00. If the laptop is asleep at a slot, the run fires once on wake. Each run:

  1. Pulls pending certificate requests from the worker's KV queue.
  2. Closes any request whose email already holds a credential, and emails that credential if it was never delivered.
  3. Freezes each submitted link to plain text: deployed pages by fetch, ChatGPT and Gemini shares by one headless browser that closes in the same run. Private and local addresses are refused at every hop, so learner links cannot reach services on your Mac.
  4. Grades every exercise twice with claude -p, no tools, from an empty folder. The orchestrator never reads learner text itself.
  5. Applies the policy: all nine L1 lessons complete, at least one build exercise passes, every submission passes in both runs (HIGH or MEDIUM confidence, evidence quote found verbatim, no injection tripwire), and the learner has proven their email.
  6. Issues the credential through a narrow machine endpoint, which emails the learner, then closes the request.
  7. Emails you a digest from v@vdr.me when anything happened. An empty queue sends nothing.
Stop it: launchctl bootout gui/$(id -u)/com.fiveinnolabs.aibadge-autorun, or set KV config:autoissue to off in the certs namespace. Revoke any credential at certs.fiveinnolabs.com/issue.

3. Email-ownership proof (why and how)

L1 requests accept unverified sign-ups, so anyone could register someone else's address, do the work, and get a credential bound to that address. Ordinary email verification does not help for NCI: Safe Links pre-clicks every link in ncirl.ie mail. A code the learner has to read and type does help, because a scanner follows links and does not type into our page.

  • After "Request certificate", the dashboard shows a code step. The worker emails an 8-digit code with no link and no digits in the subject.
  • The code is stored only as an HMAC under a server secret, expires in 15 minutes, and is bound to the learner's account and address.
  • A correct code writes emailProven {method: "code", email} on the request. The proof counts only for the address it proved, so changing the account email voids it.
  • No sign-in method skips the code. autorun accepts Google only when a linked Google identity's own email equals the address, checked with admin credentials.
  • All limits live in a Cloudflare Durable Object, CodeGuard, which handles one request at a time per address, so a guess is reserved before it is checked: 5 tries per code, 3 sends per hour and 10 per day per address, 100 sends per day per IP (a whole class can share one campus address), and 15 wrong codes lock the address for 7 days, lifting by itself at a UTC midnight.
  • A request still waiting for its code comes back as the code step when the learner reloads the dashboard.
